# KIR v1 — Kukai Revit-IR: спецификация языка и компилятора (FINAL DRAFT, Fable-A, 2026-07-16)

Статус: финализирован по итогам Фазы 0 (AUDIT.md) + 4 разведотчётов. Ждёт verify родителя.
Прямые референсы дизайна: AIDL (2502.09819, typed traceback repair), Text2MBL (2509.23713,
компилится≠верно), LLM4CAD-DSL (2606.20607, символические ID), Hypar Elements (MIT, схема),
rvt-mcp (Apache-2.0, TransactionGroup-батчи, мультиверсия), SynCode (decode-time masking),
BIM-Edit (2606.20146, раздельные geometry/semantic/topology метрики).

## 0. Нулевой принцип (унаследован из REQUIREMENTS_DRAFT)
КОРРЕКТНОСТЬ > диагностируемость > покрытие > латентность > удобство.
Молчаливый fallback запрещён; неоднозначность = типизированный отказ с кандидатами.
Op без измеримого witness-постусловия в спеку не принимается.

## 1. Конверт программы
{
  "ir_version": "1.0",            // мажор = семантика, обязательный
  "intent": "<эхо задачи, человекочитаемое>",
  "allow_destructive": false,       // rvt-mcp паттерн: delete/overwrite только при true
  "ops": [ {<op>}, ... ],           // выполняется в порядке списка после plan-стадии
}
Ответ на программу — ВСЕГДА один из двух типизированных исходов: {ok, per_op_results[], witness}
либо {refused, diagnostics[]}. Полу-успехов без явного resume-протокола нет.

## 2. Система типов (surface модели; компилятор владеет конверсиями)
- Mm, Deg, Count, Factor, Text, Bool — скаляры; ВСЕ длины только мм. Футов/UV в IR НЕ существует.
- PtXY=[x,y]мм, PtXYZ=[x,y,z]мм.
- Ref<K> — символический id (строка), объявленный более ранним op'ом; K ∈ {Level, Wall, Element,
  View, Sheet, Room, Grid} (LLM4CAD-DSL: модель ссылается на ID, координаты считает компилятор).
- Sel<K> — grounded-селектор: {"by":"name"|"element_id"|"default", "value":...}.
  Резолвится ground-стадией по живому документу; NOT_FOUND/AMBIGUOUS → отказ с кандидатами.
  "default" разрешён только где op декларирует детерминированное правило (напр. active_view),
  и резолв ЭХОМ возвращается в результате — молчаливых подстановок нет (лечит v0-болезнь
  FindLevel??lowest).
- Enum'ы — закрытые, per-op.

## 3. Регистр опов — единственный источник истины
Registry = Python-датаклассы в kukai/ir/spec.py. ИЗ регистра ГЕНЕРИРУЮТСЯ: JSON Schema
(draft 2020-12, discriminated union по "op"), GBNF/lark-грамматика (decode-time masking:
SynCode/XGrammar для 9B; serving-модели — response_format json_schema, при отсутствии
поддержки провайдером — validate-retry, ЯВНО помеченный как деградация), документация,
скелеты эмиттеров, capability-ячейки (action×object_kind) для куба Fable-B. Дрейф невозможен
by construction — рукописных копий схемы нет.

Каждый op в регистре обязан иметь:
- name, capability=(action, object_kind), since="1.0"
- params: типы, required/optional, дефолты ТОЛЬКО из общей таблицы дефолтов (ir_defaults-дисциплина)
- pre: что должно резолвиться/существовать
- post: измеримые постусловия для witness (авто-деривация: wall → LocationCurve≈(p0,p1)±tol,
  height_param≈height_mm±tol, level_id==резолв уровня)
- emit: таблица per-version эмиттеров 2021..2026 (op, не поддержанный версией → KIR-E-VERSION отказ)
- diag: коды, которые op может поднять
- topo: какие Ref он объявляет/потребляет (вход topology-гейта)

## 4. Набор опов v1 (спираль; ворота §8 на каждый — иначе не входит)
СЕМЬЯ A — AUTHORING (ядро из v0 ∪ create_element):
  create_level(elev:Mm, name?) → Ref<Level>
  create_grid(p0:PtXY, p1:PtXY, name?) → Ref<Grid>
  create_wall(p0:PtXY, p1:PtXY, level:Ref|Sel<Level>, height:Mm?, type?:Sel<WallType>) → Ref<Wall>
  create_floor(outline:[PtXY]>=3, holes?:[[PtXY]], level, type?) → Ref<Element>   // rect — сахар макро-слоя
  create_column(xy:PtXY, level, type?) → Ref<Element>
  create_window(host:Ref<Wall>, offset_mm:Mm, sill_mm:Mm, level, w?:Mm, h?:Mm, type?) → Ref<Element>
  create_door(host:Ref<Wall>, offset_mm:Mm, level, w?, h?, type?, from_space?, to_space?) → Ref<Element>
  create_room(xy:PtXY, level, name?) → Ref<Room>
  place_family(xyz:PtXYZ, symbol:Sel<FamilySymbol>, level) → Ref<Element>
  ВАЖНО (урок аудита): окно/дверь v1 задаются offset-вдоль-хоста + sill, НЕ произвольной xyz —
  «окно в воздухе» становится невыразимым, не просто проверяемым. Валидация принадлежности
  точки хосту исчезает как класс.
СЕМЬЯ B — QUERY (read-only, вне транзакций; решение Q1 — ДА, голова прод-трафика):
  query_count(kind:KindEnum, where?:[Filter]) → Count
  query_list(kind, where?, fields?:[FieldEnum], limit?) → [row]
  query_inspect(target:Ref|Sel<Element>, fields?) → row
  KindEnum — ЗАКРЫТАЯ таблица вида → правильная collector-идиома, зашитая в компилятор:
  pdf_underlay→ImageInstance/OST_RasterImages (канонический регресс-кейс: сегодняшний pdfCount=0
  СТРУКТУРНО невозможен), cad_import→ImportInstance+IsLinked=false, cad_link→IsLinked=true,
  wall/door/window/floor/room/level/grid/... Знание «где живёт X» — в ОДНОЙ таблице, заверено раз.
СЕМЬЯ C — MODIFY (минимум v1):
  set_param(target:Ref|Sel, param:Text, value:typed) → witness param-readback
  delete(target) — ТОЛЬКО при allow_destructive=true (конверт) И серверной политике.
МАКРО-СЛОЙ (детерминированная экспансия ДО verify, капы как в v0):
  stack (доказан в v0), grid_array(nx,ny,dx,dy,op-шаблон), rect_room(4 стены+room сахар).

## 5. Staged pipeline (все стадии — типизированные исходы, AIDL-петля)
parse(schema) → ground(1 батч-раундтрип, id-pin) → typecheck(единицы/рефы/enum'ы) →
plan(topo-sort DAG, транзакционные партиции, точки Regenerate из v0-инсайта walls→regen→rooms,
queries вне txn) → emit(per-version, json.dumps-эскейп всюду) → gate(6/6 :52412, прод-путь
обязателен) → execute(EXEC_PIPELINE, стемпинг) → witness(read-back → 3 РАЗДЕЛЬНЫХ вердикта:
geometry_ok / semantic_ok / topology_ok — BIM-Edit урок: топология всегда худшее место LLM,
не смешивать с compile-rate).
Repair-петля: диагностика уровня IR (§6) возвращается модели, максимум 3 попытки, дальше
отказ или явная эскалация в escape-hatch (raw C# остаётся ОТДЕЛЬНЫМ инструментом — R7).

## 6. Протокол диагностики (машиночитаемый, для самопочинки на уровне IR)
{stage, op_index, op_id, code, message_ru, expected?, got?, candidates?}
Коды: KIR-P* parse / KIR-G* ground (G-NOTFOUND, G-AMBIG+candidates) / KIR-T* typecheck /
KIR-L* plan (L-CYCLE, L-DANGLING-REF) / KIR-E* emit (E-VERSION) / KIR-C* compile /
KIR-X* execute / KIR-W* witness (W-GEOM, W-SEM, W-TOPO). Замена 2.5-минутного C#-repair
секундами IR-repair — экономика по Compiled-AI (2604.05150).

## 7. Транзакционная модель и идемпотентность
Один TransactionGroup на программу (rvt-mcp, рыночно валидировано), внутри — партиции от
plan-стадии; rollback-on-catch в каждом шаблоне (create_element-паттерн); op_id-стемп в
ALL_MODEL_INSTANCE_COMMENTS той же транзакцией (STAMP) ⇒ ретрай программы идемпотентен,
resume-from-op-K = скип уже стемпленных. Null-guard в шаблоне на каждый pinned id
(«модель изменилась после grounding» → RollBack + KIR-X-STALE).

## 8. Ворота релиза каждого опа (без прохода — опа нет)
(a) property-тесты генератором (границы, юникод, единицы round-trip mm→ft→mm);
(b) golden C# на все 6 версий, snapshot;
(c) differential: тот же интент recipe-путём vs KIR — сравнение witness-результатов
    (на одобренном девайсе, с оператором);
(d) fuzz: валидные (макро-тяжёлые) программы обязаны пройти, НЕвалидные обязаны быть
    отвергнуты с ПРАВИЛЬНЫМ diag-кодом (fail-closed доказуем);
(e) чеклист инвариантов рантайма (revit-mcp практики): units, transactions, parameters,
    selection, model state, version drift, safety, rollback — по приёмочному тесту на категорию;
(f) topology-метрика трекается отдельно от compile-rate (постоянный гейт, не разовый).

## 11. Нормативные дополнения (арбитраж координатора + вторая волна разведки, 2026-07-16)
Эти пункты — ЧАСТЬ спеки v1, переопределяют/уточняют §3-§9 где пересекаются.

11.1 АРБИТРАЖ (все пять решений утверждены):
  Q1 QUERY в v1 — ДА; граница зафиксирована: IR = исполняемая истина, вики/куб = знание для
  хвоста. Манифест куба помечает ячейки covered-by-IR / covered-by-recipe / empty — куб есть
  общая карта над обоими путями. Read-only семья B — первый прод-вход IR (нулевой риск моделям).
  Q2 отдельный tool revit_ir — ДА. Q3 канон kukai/ir/ в backend-git — ДА (семвер, без тихих
  изменений). Q4 witness всегда, norm-контракты opt-in — ДА. Q5 registry → capability_vocab,
  куб потребляет реестр — ДА; изменения оси только через координатора.

11.2 ДВУХУРОВНЕВЫЙ VERSION DRIFT (усиление §3-emit и §8):
  Revit ≤2024 = .NET Framework 4.8; 2025-2026 = .NET 8 — дрейфует не только API, но и рантайм
  (языковая версия C#, доступность API BCL). Эмиттеры в registry ведут ДВЕ оси: api_variant
  (какой вызов) и runtime_variant (какой C#/BCL допустим). Практика pyRevit-паттерна
  (#if REVIT20XX_OR_GREATER) адаптируется так: KIR эмитит per-version ПЛОСКИЙ код (без директив —
  гейт компилирует каждую версию отдельно), но таблица эмиттеров организована директив-подобно:
  вариант объявляется как since/until, не копипастой. Property-тесты §8(a) гоняют ОБЕ оси.

11.3 ТИПИЗИРОВАННЫЕ ЕДИНИЦЫ — ВИТРИННАЯ ФИЧА:
  Разведка: compiler-enforced размерности не существуют ни в одной LLM-BIM системе (везде
  промпт-дисциплина). Инвестиция сверх минимума: (а) все Mm/Deg — newtype в spec.py, а не int;
  (б) property-тест round-trip mm→internal→mm на КАЖДЫЙ эмиттер; (в) в публичных материалах
  (HF-карточка, статья) фича подаётся первой.

11.4 ТОПОЛОГИЯ В WITNESS С ПЕРВОГО ДНЯ (усиление §5):
  BIM-Edit: у лучшей фронтир-модели geometry 68.9 vs topology 37.8 (F1 узлы+рёбра, вес
  отношений 70%) — связи есть систематически худшее место LLM. Нормативно: post-условия
  СВЯЗЕЙ (window.host==созданный wall.Id, wall.level==резолвленный level.Id, room нашла
  замкнутую границу) обязательны в witness каждого authoring-опа v1 — не в v2, не opt-in.
  Отчёт witness всегда несёт три раздельных числа: geometry_ok/semantic_ok/topology_ok.

11.5 ROLLBACK — ЯДРО ПРОДУКТА, НЕ ДЕТАЛЬ:
  BIM-Edit-урок «failed runs ≠ zero-score»: частичные мутации до сбоя — признанная беда
  систем без транзакционной дисциплины. Позиция KIR: частично изменённая модель пользователя —
  худший исход из возможных, хуже отказа. Подтверждено в §7; поднято в топ RISK_MATRIX (R2).

11.6 ВНЕШНИЕ ПЛАНКИ (для honesty в метриках):
  CAD-Coder Valid Syntax Rate 88-94%, CAD-RL executability 99.63% — это планка «просто
  синтаксис/исполнимость», её KIR обязан бить by construction (~100% через schema+gate).
  НАША планка — семантика через witness (geometry+semantic+topology), сравнение с
  BIM-Edit-подобной методологией; compile-rate в отчётах никогда не подаётся как успех.

11.7 ПРИОРИТИЗАЦИЯ ОПКОДОВ:

## 12. Методологический слой (финальный разведпакет, нормативно)
12.1 АРХИТЕКТУРНОЕ ИМЯ ПАТТЕРНА — Safety Sandwich (Compiled AI 2604.05150 + Fowler 07-2026):
  LLM-шаг зажат между валидацией (schema+typecheck ДО) и детерминированной логикой (compiler+
  witness ПОСЛЕ); «whole classes of malformed scenarios simply do not compile». В BIM паттерн
  никем не занят — KIR застолбляет.
12.2 POLICY-GATE НА ПЛАНЕ, НЕ НА ИСХОДНИКЕ (Sentinel/OPA-паттерн): семантические политики
  (destructive-ограничения, бюджеты объёма изменений, номенклатурные правила) проверяются на
  IR/plan-стадии — IR есть инспектируемый diff здания. Сгенерированный C# политиками не
  инспектируется никогда (он — артефакт, не интерфейс).
12.3 ОГРАНИЧЕННАЯ ВЫРАЗИТЕЛЬНОСТЬ КАК ПРИНЦИП (Dhall-total/Starlark-hermetic): в KIR НЕТ
  произвольных циклов/рекурсии/условий — только фиксированные макро-паттерны с капами
  (stack, grid_array, series). Следствия: тотальность (non-termination невыразим), разрешимый
  typecheck, PBT-генератор по typing judgment возможен. Запросы «нужен цикл» → новый макрос
  через registry-ревью, не расширение языка.
  ПРЕЦЕДЕНТ 2026-07-29 (series): третий макрос добавлен именно этим путём. Замер на башне
  Эйфеля показал, что кусочно-меняющийся параметр (полуширина по высоте) выразим только
  перечислением — 118 балок литералами за 7 раундов против трёх строк C#. Существующий
  stack.transform подменой не был: его сужение — ОДНА прямая от низа к верху, и лучшая
  возможная такая прямая промахивается по настоящему профилю на 20.62 м (69%) на отметке
  первой площадки. При том, что 85% времени хода занимает раздумье модели, единственное,
  что стоит оптимизировать, — СМЫСЛ НА РАУНД. `series` повторяет шаблон N раз, подставляя
  числа с кусочно-линейного трека по индексу. Это НЕ цикл: k-й повтор — чистая функция от
  k, развёртку считает компилятор, программа остаётся данными, границы — MAX_SERIES_OPS
  (200) и MAX_TRACK_NODES (32).
  ГРАНИЦА, КОТОРУЮ МАКРОСЫ НЕ ПЕРЕХОДЯТ: подстановка ссылок ($имя, -$имя, $имя@next,
  -$имя@next) КОМПОЗИЦИИ НЕ ИМЕЕТ — четыре формы, ни приоритетов, ни вычислителя. Минус
  здесь не арифметика, а зеркало симметричного здания. Появление в этом месте бинарного
  оператора («$a + $b») превратит подстановку в интерпретатор и сломает 12.3; такой запрос
  закрывается НОВЫМ МАКРОСОМ, а не новой формой ссылки.
  ОДНОСТОРОННОСТЬ: макрос — свойство пути «модель → здание». Разбор чужой модели макроса не
  вернёт (в Revit нет макросов, есть элементы), поэтому мерить макрослоем покрытие разбора
  нельзя, а roundtrip на нём не замыкается.
12.4 ПРОТОКОЛ ЭМИССИИ ДЛЯ 9B — REASONING-THEN-STRUCTURE (2606.09410, 2605.02363: JSON-mode
  с первого токена = −10-30% reasoning у малых моделей): фаза 1 — свободное рассуждение;
  фаза 2 — constrained-декодинг ТОЛЬКО IR-блока (SynCode/XGrammar маска включается на
  открывающем токене блока). Serving-модели — то же через двухфазный промпт.
12.5 HOARE-ТРОЙКИ И COMMIT-GATE ({P}op{Q}, ToolGate 2601.04688; ContractSpec 2602.22302):
  пре/пост каждого опа — из registry (§3). ДВУХЪЯРУСНЫЙ witness: (1) in-transaction guard —
  после опов Regenerate → read-back → проверка постусловий ВНУТРИ транзакции; нарушение →
  RollBack, НЕ Commit (частичная мутация невыразима как исход); (2) post-commit независимый
  probe — истина для записи/телеметрии (create_element-паттерн). Runtime-бюджет контрактов
  <10ms — постусловия компилируются в прямые сравнения, не в интерпретацию.
12.6 ТЕСТОВЫЙ СТЕК (все 5 обязательны; уточнение §8):
  (a) golden по chibicc-дисциплине: обновление ТОЛЬКО явным флагом + ревью diff человеком/
      координатором — auto-regenerate запрещён;
  (b) PBT: генератор well-typed-BY-CONSTRUCTION (по typing judgment — Palka/Hughes ISSTA'11,
      Hypothesis st.recursive), НЕ grammar+отбраковка. Инварианты: компилятор никогда не
      паникует; well-typed IR ⇒ Roslyn-чистый C# на всех 6 версиях;
  (c) reference-интерпретатор IR как ОРАКУЛ (Csmith-подход): чистая Python-модель эффекта
      (units, preconditions, счётчики/геометрия изменений) → сравнение с фактическим эффектом;
      для критичных операций — N-candidate self-consistency с diff-по-эффекту (PV-SQL);
  (d) negative-fuzzing валидатора: невалидный IR ⇒ структурная диагностика, panic исключён;
  (e) differential против recipe-пути (§8c, подтверждено разведкой).
12.7 КОНТРАКТ ДИАГНОСТИКИ (уточнение §6, по rustc --error-format=json):
  {op_id, span, error_code, message_ru, suggested_replacement?, applicability:
  machine-applicable|maybe-incorrect, rendered}. Сырая ошибка C#/Roslyn модели НЕ отдаётся
  никогда — транслируется к породившей IR-операции (SACTOR-паттерн). Доказанная экономика:
  structured диагностика +5.95 п.п. resolve rate, −23% токенов (SHERLOC). Retry cap = 3.
  Фидбек детерминированный, НЕ self-evaluation (Olausson: bottleneck именно там; Siemens:
  даже бинарный compile-сигнал 7%→70%).
12.8 АУДИТ ENUM'ОВ: каждое enum-поле схемы обязано иметь escape-значение (unknown/other),
  семантика которого — типизированный ОТКАЗ/handoff в recipe-путь, НЕ угадывание ближайшей
  категории. KindEnum.other ⇒ KIR-G-UNSUPPORTED-KIND + маршрут в вики-путь.
12.9 ЧИСЛОВЫЕ ГРАНИЦЫ: JSON-schema min/max декодерами НЕ enforce'ится — единственное
  доверенное место числовой валидации = typecheck-стадия компилятора. Схема несёт границы
  только как документацию.

Нарушение закона — ошибка сборки или прогона, не пожелание ревьюеру.

### 18.1. Закон переписи (Any-Model — зеркало §14 для обратного пути)

На ЛЮБОЙ модели каждый прогон decompile обязан свести бухгалтерию документа:

    |элементов в документе| = поднято_в_опы
                            + атомов (каждый с типизированной причиной)
                            + не_читалось (каждая строка с типизированной
                              причиной: category_outside_table | budget_cut |
                              workset_closed | page_refused)

Знаменатель ЛЮБОГО процента покрытия — вся левая часть, не выборка таблицы
категорий. Перепись — один дешёвый полномодельный проход (категория → счётчик),
исполняется ВСЕГДА. Расхождение тождества = ошибка прогона (typed), не
предупреждение. Паспорт и run.json печатают все четыре числа явно; строка вида
«категорий в модели X, читается Y, не покрыто Z элементов» обязательна.

Принуждение: сверка тождества в pipeline; CI-фикстура с категорией вне таблицы
обязана дать ненулевое «не_читалось», а не тихие 100%.

Следствие (лестница верности, DECOMPILE 0.6.2): ярусы Gb/Gm остаются «на
складе» — v1.2 требует не реализации лестницы, а ЗАПРЕТА ЛЖИ на её отсутствии:
элемент с кривой не-Line без строки бокового индекса — атом с причиной
curve_kind_unsupported, НИКОГДА не хорда. L0 обязан различать вид кривой
(curve_kind: line | arc | other) в самом захвате.

### 18.2. Закон квитанции (каждый срез оставляет след)

Любой бюджет, таймаут, непарсируемая строка, неузнанная форма ответа обязаны
эмитить запись {element_id, typed_reason} — дисциплина curve_extract становится
ОБЩИМ контрактом всех боковых экстракторов (ответ = rows + failures, оба ключа
обязательны; отсутствие failures — ошибка схемы). Стадия сверяет
|запрошено| == |rows| + |failures|. Одна плохая строка изолируется в failure с
id элемента — прогон живёт. Агрегат failures поднимается в run.json и паспорт
с разбивкой по typed_reason; артефакт, переиспользуемый resume-логикой, несёт
счётчик строк для сверки при переиспользовании.

Принуждение: общий валидатор контракта боковой стадии; тест «одна битая строка
⇒ ровно один failure, ноль упавших прогонов».

### 18.3. Закон свидетеля (читай ту ось, которую подписываешь)

Обязательство с kind=geometry разряжается ТОЛЬКО чтением геометрии
(LocationCurve/LocationPoint/bbox); kind=topology — чтением связи
(Host/LevelId/системная принадлежность); kind=semantic — чтением
параметра/состояния. Чтение номера параметра НЕ разряжает геометрическое
обязательство. Оп, чей заявленный эффект нечем прочитать, обязан либо
реализовать эффект, либо снять параметр из схемы; «записано, но не движет»
допустимо ТОЛЬКО как kind=semantic с явным текстом об этом в post.

Конкретные применения (из аудита):
- create_wall.location_line: либо смещение p0/p1 вдоль плановой нормали на
  factor×width (константа _WALL_FACE_HALF_WIDTH_FACTOR заведена именно для
  этого), либо параметр покидает схему; текущая форма — запрещена;
- уклоны кровли: соответствие ребро↔кривая устанавливается ГЕОМЕТРИЧЕСКИ
  (ближайшая середина), не порядком массива; расхождение числа кривых —
  типизированный отказ; свидетель уклонов читает уклон рёбер, не только
  суммарный подъём bbox.

Принуждение: линт сертификата — маппинг kind → допустимые формы reader_cs;
обязательство без легального читателя не проходит импорт реестра.

### 18.8. Поправка к 18.3 по живому замеру (2026-07-28, нормативно)

Частное предписание 18.3 для create_wall.location_line («смещение p0/p1 на
factor×width либо снятие параметра») опиралось на посылку, опровергнутую
живым замером (docs/2026-07-28-location-line-measurement.md, 724 настоящих
непентральных стены, разброс 1e−13): LocationCurve в Revit — ВСЕГДА
центральная плоскость тела при любом значении WALL_KEY_REF_PARAM; правило не
смещает ни ось, ни тело, а решает лишь, какая плоскость переживёт смену
толщины. Тело пересобранной стены совпадает с оригиналом и без смещения;
предписанное смещение ВНЕСЛО БЫ ошибку в полтолщины.

Нормативный исход: применён третий путь самого 18.3 — «записано, но не
движет» как kind=semantic с явным текстом в post; обязательство
location_line заведено в сертификате (KIND_SEMANTIC, условное); линт оси
свидетеля (test_witness_axis_honesty) — постоянный механизм принуждения.
Общий закон 18.3 не меняется. Урок закона: предписания уровня конкретного
опа в спеке обязаны опираться на замер, а не на модель поведения API в
голове аудитора — сам аудит от этого требования не освобождён.

## 19. МИССИЯ-ЗАГОЛОВОК — вайбКАД (директива оператора, 2026-07-28, нормативно)

«Мы открываем доступ к тому, чтобы нейронке стало ЛЕГКО вайбКАДить».

Вайб-кодинг случился потому, что между автором и машинным кодом встал слой, в
котором модель сильна. Зданиям такого слоя не дали: нейронку сажают писать
Revit-C#, где ~60% её прод-ошибок — борьба с поверхностью API (§15.2), при
том что в декларативной графике (HTML и подобное) та же модель заметно
сильнее. KIR — этот слой для BIM: модель сосредотачивается на 3D, геометрии
и составе; транзакции, версии API, единицы, хосты, свидетели и откаты — у
компилятора. Аналогия точная: мы делаем для зданий то, что HTML сделал для
вёрстки — автор описывает ЧТО, движок владеет КАК.

19.1 ВайбКАД-критерий (применяется к каждому решению по языку): «стало ли
  модели легче выразить здание, оставаясь в геометрии?» Сахар уровня
  stack/defaults — продукт, а не удобство (замер 27.07: defaults снял 86%
  отказов). Расширение языка, которое заставляет модель думать по-сишарпному,
  отклоняется независимо от его полезности компилятору.

19.2 Иерархия не меняется: §0 (КОРРЕКТНОСТЬ > диагностируемость > покрытие >
  латентность > удобство) и законы §18 стоят НАД миссией — лёгкость, купленная
  молчаливой неверностью, есть провал миссии, потому что модель, обученную и
  оцененную лживым экзаменатором, вайбКАДить не научить.

19.3 Метрика миссии — модельная сторона, не только компиляторная: на
  фиксированном корпусе зданий-заданий сравниваются попытки-до-зелени, раунды
  ремонта и витнес-тройка у модели, эмитящей KIR, против той же модели на
  C#-пути. Стенд: scenario_bench + дожо (kir_dojo/kir_eye, судья — компилятор
  офлайн). Число этой метрики — главный публичный аргумент проекта, когда
  лаборатория откроется.
