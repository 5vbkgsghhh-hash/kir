   новой тёмной волны, пока одна тёмная вещь не доехала до live (ПРОВОДКА).**
3. **Узкое место — время оператора.** Фабрика кода работает; очередь вещей,
   которые может сделать только оператор: rc6/флот, Windows-тест клиента,
   live-прогоны (двери/колонны/группы не исполнялись живьём), трансфер IFC.
4. **Асимметрия доказательств.** Всё доказано на ОДНОМ здании. Универсальность
   доказана отрицательно (нет хардкода), не положительно (N разных зданий).

   witness-дисциплина + корпус форм/приоров + верифицированная вики. Компилятор

# ЧАСТЬ 1. СЕВЕРНАЯ ЗВЕЗДА И ГЛОБАЛЬНЫЕ ИНВАРИАНТЫ

**Северная звезда:** live-идемпотентность
`decompile(rebuild(decompile(M))) == decompile(M)` на корпусе зданий — ночной
прогон, отчёт. Это одновременно метрика «лучшего компилятора» и единственно
честный верификатор для RLVR.

**Инварианты каждой волны (нарушение = провал ревью):**
- I1 Универсальность: ноль LOT31/русскоязычного хардкода в логике.
- I2 Fail-closed: любой сбой = типизированный отказ; молча неверный элемент
  невыразим.
- I3 Байт-стабильность: старые программы/program_hash/канон-хэши/goldens —
  байт-в-байт, если явно не версионировано (MERKLE_VERSION-стиль).
- I4 Детерминизм: без часов/random/непорядоченных коллекций на путях вывода.
- I5 Аддитивно+инертно: новое за флагом default OFF; frozen L0-схема не
  трогается (расширения — через params-словарь и side-индексы).
- I6 Live только admin-устройство a6d7d14340bc599817ae7e6896182ca0; kill-switch
  allowlist уважается; фронт-раннер прод-порты не трогает.
- I7 Мост-бюджеты: НИКОГДА не per-element brute-force по всей модели (урок
  bridge-wedge). Пагинация, кооперативные тайм-бюджеты, symbol-дедуп,
  resumable-чекпоинты — как в extract.py.
- I8 Verify-after: волна = worktree, НЕ коммитить; лид ревьюит+гейтит+коммитит.
  Suite-база: 13 environmental failed / 1068 passed; дельта чистая. Гейт 90×6=0.
- I9 Экономный пейсинг: 1-2 субагента одновременно.

**Не делать (решено, не пере-обсуждать):** полный C#-AST (хватает
witness-модели); LLM-repair на KIR-пути; маскирование execute_revit_code;
воскрешение «гадающего судьи»; прямой API-протокол вместо эмиссии C#
(Roslyn-гейт = бесплатная 6-версийная статика — преимущество).

## A1. ПРОВОДКА — decompile/rebuild как admin-инструменты прод-сервиса
**Кто почувствует:** оператор немедленно (декомпайл любой открытой модели одной
командой); все последующие волны получают live-путь.
**Якоря:** `serving.py` (паттерн handle_revit_ir: гейт ADMIN_DEVICE + flag,

`sketch_extract.build_sketch_extract_cs`, `curtain_extract`, `family_placement_extract`,
`group_extract`; `lift_cache.cached_lift_document_detailed(enabled=True)` (64x
доказан), `fold/name/verify/passport`, `decompile/orchestrator.py` (244 строки —
ПЕРЕЧИТАТЬ перед волной: возможно, половина оркестрации уже есть).
**Прибитые решения:**
- Два инструмента: `revit_decompile` (read-only) и `revit_rebuild` (write),
  флаг `KUKAI_KIR_DECOMPILE=stage2`, гейт как у revit_ir (flag AND admin device),
  повторная проверка в диспатче.
- Executor = обёртка над RevitExecutionPipeline.run_declarative (как snapshot в
  serving), timeout как _SNAPSHOT_TIMEOUT_MS, ретраи EXTRACT_RETRIES.
- Персист: `backend/data/decompile/<doc_stamp>/` — L0.jsonl+checkpoint,
  side-индексы (*.json), lift-кеш, tree.pkl, passport.md, verify.json.
  change_stamp = doc title + UIDoc hash от моста; resume по чекпоинту.
- Порядок: metadata→categories (штатный extract) → side-индексы ПАЧКАМИ по
  спискам id из L0 (curve: только стены/балки с geom curve; sketch: полы/кровли/
  лестницы; curtain: стены; family_placement: все FamilyInstance-категории;
  groups: все) → lift(cached) → fold(с group_index) → name → verify → passport.
- rebuild:材ериализатор A3 (same_document) → chunked compile_program →
  emit_program(isolation="per_op", postconditions="report",
  disallow_wall_joins=True) → результат с per-op refused-списком. Опция
  `offset_mm` (сдвиг области) и `dry_run` (только компайл-гейт, без исполнения).
- Прогресс: каждый этап пишет status.json (этап/счётчики/ошибки) — фронт может
  поллить; никаких блокировок UI-потока дольше бюджета этапа (I7).
**Тесты-приёмка:** оркестратор офлайн на фикстурах (моканый executor) — полный
прогон до passport; resume после обрыва на каждом этапе; live-приёмка на admin:
декомпайл открытой модели до passport + rebuild dry_run 6/6. Suite/гейт-дельта
чистые.
**Размер:** M-L (2 подволны: офлайн-оркестратор; serving-обвязка+live).

## A2. Witness-объектная модель (Emission IR light) + registry-онтология
**Кто почувствует:** внутренняя корректность навсегда (класс F3 умирает по
построению), member-POSTs групп разблокируются, толерансы централизуются.
**Якоря:** `authoring.py` (26 эмиттеров, форма post-блоков однородна),
`translation_cert.py` (REFINEMENT, verdict-span правило), `registry_base.py`
(OpSpec), `struct_emit.py` (импортирует приватные хелперы — обновить вместе).
**Прибитые решения:**
- Новый модуль `kukai/ir/emit_model.py`:
  `WitnessCheck(obligation_key, reader_cs, verdict_cs, message, tol_key,
  style: "guard"|"else_block"|"plain")` + `render_post(oid, checks) -> str`.
  Эмиттеры возвращают `(decl, create, posts: list[WitnessCheck], readback)`;
  `emit_program` рендерит. create/decl/readback остаются строками (80/20).
- БАЙТ-ГАРАНТИЯ: рендер обязан воспроизводить текущие байты. Механизм: ДО
  рефакторинга снять фикстуры «старых байтов» для всего golden+gate-корпуса
  (скрипт пишет emitted C# в files); тест `test_emit_model_byte_parity`
  сравнивает новый рендер с фикстурами построчно. Волна идёт по три эмиттера
  (первая тройка: wall/level/grid — доказывает жанры guard/else/plain), дальше
  механически.
- Cert: для мигрированных опов REFINEMENT читает obligations прямо из
  posts-объектов (`witness_source="model"`); span-правило остаётся для
  немигрированных; после полной миграции span-код удаляется.
- Registry-онтология: OpSpec получает поля `tolerances: dict[str, float]` и
  `obligations_builder` (или ключи в WitnessCheck ссылаются на OpSpec) — 4
  параллельные таблицы (spec/schema/cert/толерансы) складываются в одну;
  `audit_registry_coverage` вырождается в тривиальную проверку.
- Групповые member-POSTs: `_emit_group` включает member-posts как WitnessCheck'и
  (конфликт conditional-absent с `.Name` исчезает — obligations теперь по
  ключам, не по подстрокам).
**Тесты:** byte-parity на всём корпусе; cert-адверсарий из аудита (mutation2
теперь ЛОВИТСЯ — перевернуть characterization-тест); registry-lint.
**Размер:** M (механика × 26, но однородная).

- `instantiate(template, bindings) -> leaves` (обратный проход), затем A3 →
  программа. ТЕОРЕМА T-TPL (property-тест): для каждого исходного вхождения
  `instantiate(anti_unify(G), bindings_k) == G_k` байт-в-байт по канону.
- Расширение шаблона (k > исходного N): слоты с прогрессией экстраполируются,
  свободные слоты требуют значений (типизированный отказ, не guess).
**Тесты:** синтетика: башня 5 этажей dz=3300, вариации высот стен; T-TPL;
экстраполяция на 7 этажей → re-lift-канон совпадает с ожиданием; lot31: отчёт
«сколько шаблонов, сколько слотов, роли» (без экстраполяции — только вывод).
**Размер:** M-L. Зависимости: только merkle (можно параллельно с A-волнами).

## B2. Нормо-тайпчекер v1 — отчёт по дереву (law-packs)

- Три правила v1 (только по данным, которые уже есть в дереве):
  N001 жилая комната < min_area (тип комнаты — _HABITABLE_RE-класс из name.py,

**Тесты:** фикстурные деревья на каждое правило (позитив/негатив/границы);

# ЧАСТЬ 6. САМОАУДИТ ДИЗАЙНА (v1.1) — что я улучшил бы, дополнил, исправил
**Адверсариальное ревью собственного документа тем же методом, что аудит кода.
Правки ниже — ОБЯЗАТЕЛЬНАЯ часть дизайна (перекрывают Части 3-4 при конфликте).**

## Найденные дыры и исправления

### Д1. [A1, КРИТИЧНО] Контракт нагрузки моста не прибит — а именно там живёт wedge
Дизайн говорил «бюджеты/пагинация», но freeze-инцидент учил: любой долгий
UI-thread-вызов вешает Revit. Декомпайл 90k = сотни раунд-трипов минутами при
ОТКРЫТОМ у пользователя Revit. **Прибиваю: Bridge Load Contract** — (а) целевая
длительность одного вызова ≤2s (бюджеты этапов уже это дают — сделать SLO и
мерить в status.json); (б) межвызовный yield (пауза ≥200мс между пачками —
UI дышит); (в) отменяемость: status.json содержит `cancel_requested`, оркестратор
проверяет между пачками, обрыв = чистый resume по чекпоинту; (г) прогресс
оператору всегда виден. Без этих четырёх пунктов A1 не принимается.

### Д2. [A1, КРИТИЧНО] change_stamp был помахан рукой — прибиваю консистентность
Правка модели ПОСЛЕ категорий, но ДО side-индексов = молчаливый рассинхрон
(curve-индекс кросс-чекается с p0/p1 и fail-closed отбрасывается, но
family_placement/groups такой защиты не имеют). **Прибиваю: probe-протокол** —
дешёвый зонд (макс-ElementId + счётчик элементов по категориям) снимается до и
после КАЖДОГО этапа; расхождение = этап помечен stale → авто-повтор этапа один
раз → снова расхождение = типизированный отказ «модель редактируется во время
декомпайла». Контракт для оператора: не редактировать во время прогона.

### Д3. [A5, КРИТИЧНО-БЕЗОПАСНОСТЬ] Идемпотентность — только на КОПИИ модели
Провал cleanup = осиротевшие Δ-элементы в рабочем документе. **Прибиваю:**
A5 запускается ТОЛЬКО на копии (оператор открывает копию — как в прежних
live-тестах), плюс: (а) датумы исключены — create_level/create_grid НЕ
пересобираются (имена уникальны → ложные отказы), уровни/сетки пинятся
существующими, сравнение = только не-датум опы; (б) в отчёте — явный список
ОЖИДАЕМЫХ классов отказов (комнаты вне ограждения и т.п.), чтобы % не врал.

### Д4. [A2] Миграция эмиттеров должна быть инкрементальной — прибиваю адаптер
Смена сигнатуры _EMITTERS разом = большой недробимый дифф (struct_emit,
native_group, cert, тесты). **Прибиваю:** переходный контракт — post может быть
`str | list[WitnessCheck]`; emit_program рендерит оба; cert потребляет модель
там, где она есть, span-правило — где строка. Волна дробится по 3 эмиттера с
byte-parity после каждой тройки. Span-код удаляется только в финале.

### Д5. [A3] Два непрозвученных закона чанкования
(а) **Хост-атомарность**: стена + все её hosted (двери/окна) = неделимая единица
чанка (иначе ref через границу). (б) **Комнаты — в хвостовые чанки**: комнате
нужно ограждение УЖЕ В МОДЕЛИ; внутричанковый regen это не решает для стен из
следующего чанка. Порядок: датумы(существующие)→стены+hosted→прочее→комнаты.

### Д6. [Ф, ОШИБКА В ДИЗАЙНЕ] Фингерпринт из display-строк — неверно
AsValueString зависит от единиц/локали документа → один и тот же тип в метрической
и имперской моделях даёт разные fp — ломает саму цель (кросс-док матч).
**Исправляю:** fp = sha1 по СЫРЫМ значениям (AsDouble во внутренних единицах,
invariant-формат «G17»; AsInteger; String как есть; ElementId-параметры —
ИСКЛЮЧИТЬ из fp, они непереносимы). Имя параметра — по BuiltInParameter enum-имени
где есть (locale-независимо), иначе по имени с пометкой.

### Д7. [B1, УПРОЩЕНИЕ] Анти-унификация строится НА component-library, не рядом
Вместо параллельной группировки: скелет-канон (числа→#) вычисляется над
ЛОКАЛИЗОВАННЫМИ канонами (node_origin-базис, reuse _translate_leaf) →
ComponentDefinition'ы с одинаковым скелетом сливаются в TemplateDef
{skeleton, slots, origin-байндинг как у ComponentInstance}. Шаблон = обобщённый
компонент. Меньше нового кода, теоремы наследуются (T-TPL поверх C1/C-RT).

### Д8. [B2] Ложные срабатывания «жилая без окна»
Панорамное остекление = curtain-стена без OST_Windows → ложный флаг.
**Прибиваю:** стена, присутствующая в curtain-индексе с панелями, считается
светопрозрачной; окно на смежной стене засчитывается обеим комнатам. В отчёте
у правила всегда есть колонка «основание» (какая стена/окно).

### Д9. [A4] DirectShape не для всех категорий
DirectShape.CreateElement валиден не для всякой категории (OST_Rooms и др. —
нет). **Прибиваю:** whitelist категорий escrow проверяется тестом через
DirectShape.IsValidCategoryId-семантику (гейт-компиляция + live-приёмка);
вне whitelist — честный атом остаётся атомом.

### Д10. [НОВАЯ ВОЛНА A7] Delta-исполнитель (retire+emit)
Дизайн пересобирал только «добавить». Для checkout/пересадки/live-проекции нужен
исполнитель дельты: retire = chunked delete по id (существующий op delete,
allow_destructive, admin), затем emit-чанки. Якорь: rebuild.DeltaProgram уже
типизирован. Малая волна, разблокирует B3-checkout и B5. После A1+A3.

### Д11. [B4] Отчёт даунгрейда
2026→2021: фичи 2022+ (holes и т.п.) дают E003 — план обязан включать
«downgrade report»: что неперепредставимо и почему, ДО исполнения (dry_run).

### Д12. [ПРОЦЕСС] Кому какая волна
